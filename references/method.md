# 方法说明（Methodology）

## 总体架构：语义规划 + 确定性执行的分工

转换链路按“哪部分最容易出错”决定自由度：语义理解（主线、主张、讲稿）由执行 Agent 完成，受提示词与 schema 约束；所有需要稳定复现的动作（PDF 解析、区域裁剪、占位符填充、渲染、越界检测）由幂等 Python 脚本完成。脚本不依赖任何 LLM API，因此在任何 harness 下都能直接运行；Agent 无法完成语义规划时，确定性兜底规划器仍可交付可复核的完整结果。

## 关键方法

1. **论文主线提取**：以六要素（问题/缺口/方法/关键证据/贡献/局限）为抽取骨架，证据按证明力排序而非按论文页序；页序由论证逻辑决定，允许重排图表顺序。
2. **caption-mention 双向索引**：解析时同时建立图表 caption 索引（编号、页码、逐字图注）与文内 mention 索引（“如图 3 所示”的页码与上下文），规划证据页时二者交叉验证，从机制上消除编号错位与引用不存在的图。
3. **图表区域裁剪**：联合内嵌图像矩形与矢量绘图矩形，聚类后按“caption 正上方且水平重叠”配对，200 DPI 输出；无法定位时回退到 caption 上方区域裁剪与整页渲染，并标记降级类型。裁剪保留原图信息，不做内容裁切。
4. **证据类型与出处标注**：依据 caption 关键词自动标记示意图/数据图、本文结果/他人结果；图注、条件、样本量逐字保留，防止示意图被当数据、他人结果被当本文贡献。
5. **模板占位符映射**：解析每个版式的占位符类型与几何，角色到版式按评分选择；缺失时在实测安全区内添加文本框，母版、主题色、字体方案、页脚永不被覆盖。
6. **备注与页面分离生成**：备注字段独立承载过渡、强调点与被问到时的补充证据，QA 用相似度检查禁止备注复读页面文字，并检测跨页备注雷同，确保逐页差异化。
7. **确定性文本适配**：按 CJK/拉丁字符宽度模型与行高估算容量，在字号下限内收缩；最终以渲染 PDF 上的真实形状 bbox 做越界裁决，而不是仅靠估算。
8. **字体安全策略**：运行时探测已安装字体，按度量兼容表替换并记录；渲染后核对嵌入字体子集，中文内容无 CJK 字体时按高风险告警。
9. **渲染级 QA 闭环**：溢出、字体、编号、页码、逐字引文、数字单位、备注、页数上限统一在 QA 报告中分级，驱动至多两轮修复，残余问题如实保留。

## 边界与适用范围

- 负责“论文内容如何变成可讲、可核验、可编辑的学术 PPT”；不负责论文精读结论生成、科研绘图的图形设计美化、学术写作润色。
- 输入以学术论文 PDF 为主，兼容中英文、含图/表/公式的实证研究；对扫描件、加密文件、无模板等情况提供降级路径，降级结果明确标注。
- 事实唯一来源是实际输入文件与原始论文；领域标签、先验知识不得用于补造数据。
- 可复现性：每个变更动作进入 `change_records`，相同输入、相同模板、相同软件版本重复运行得到同一版式。

## 维护

- 依赖与版本见 `requirements.txt`；脚本按阶段独立可运行，也可通过 `run.py` 统一编排。
- 新增解析规则时优先扩展 `paper.json` 的结构化字段，保持 schema 向后兼容；失败处置同步更新 `exceptions.md`。
